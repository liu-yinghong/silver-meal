## 项目简介

银龄放心单是一个**适老点餐 项目（Demo）**，目标用户为恢复期独居老人及其家属。老人可通过日常语言输入需求，系统智能推荐三份适合的餐食，家属在另一端设置饮食规则（预算、偏好、禁止食材），下单后模拟完整的外卖流程（制作→配送→送达→确认收餐）。异常情况（如送达后老人长时间未确认）会自动提醒家属。

## 核心功能

- **智能推荐**：老人用日常语言说出需求，大模型解析为口味/预算/关键词，返回三份推荐餐食及理由；当菜单里没有老人想吃的餐食时，由大模型生成解释提示语并推荐合适的替代餐食
- **家属守护**：家属端设置单餐预算、饮食偏好、禁忌食材等规则，推荐全程硬性遵守；实时查看老人订单与配送状态，老人超时未收餐自动提醒
- **适老体验**：大字体、暖橙色调、按住说话语音点餐；全程模拟外卖流程（制作→配送→送达→确认收餐），餐品均展示实拍图
- **离线降级**：未配置或调用大模型失败时自动切回本地规则，推荐主链路不断；后端断开时明确提示，不产生任何模拟假数据

### 核心设计原则

1. **依赖倒置**：`core/` 业务逻辑层依赖 `repositories/` 的抽象接口（Protocol），而非具体实现
2. **适配器模式**：`adapters/` 层隔离 Web 框架，更换 API 风格（如淘宝小程序）只需新增适配器
3. **状态机**：订单状态流转在 `order_service.py` 中统一管理，状态路径清晰可控
4. **适老设计**：前端大字体、高对比度、暖色调，符合老年人使用习惯

## AI 意图解析（真实大模型，可选）

推荐链路中的「理解老人需求」这一步默认调用**阿里云百炼（DashScope）qwen3.7-max**，将自然语言解析为结构化需求（口味偏好 / 价格区间 / 食材关键词），推荐理由仍由本地规则引擎生成，保证可回溯与断网可用。

- **模型：** `qwen3.7-max`（OpenAI 兼容端点 `https://dashscope.aliyuncs.com/compatible-mode/v1`）
- **API Key：** 读取本机用户环境变量 `OPENAI_API_KEY`，无需写入代码
- **超时与降级：** 单次调用超时 20 秒、不重试；任何失败（无 Key / 断网 / 超时 / 解析失败）自动切回本地关键词解析，绝不阻断主链路
- **响应标记：** `/api/meals/recommend` 返回 `ai_mode`：`remote` 表示真实大模型解析，`local` 表示本地降级；老人端会据此显示「正在用本地餐品规则继续」
- **配置：** 可通过 `LLMService(api_key, model, base_url, timeout)` 构造参数覆盖，测试中可用 `use_remote=False` 强制本地
- **未命中兜底：** 当老人提到的餐食在菜单中不存在时，由大模型生成一句口语化的解释提示语（说明"没有找到"的原因 + 已推荐什么替代餐食），并挑选符合家属规则的替代推荐；大模型不可用或超时时自动降级为本地模板提示语，推荐流程不受影响

> **语音识别（老人端按住说话）**：同样读取 `OPENAI_API_KEY` 调用百炼 Paraformer。未配置 Key 时语音会提示"无法识别，请直接输入文字"，不影响文字输入下单。首次按住说话时浏览器会询问麦克风权限，允许后即可正常使用（已优化为仅询问一次、会话内复用）。

### 如何配置 `OPENAI_API_KEY`（可选，启用大模型/语音）

不配置也能运行（自动降级本地），但推荐配置以启用真实大模型与语音识别：

1. 到 **阿里云百炼控制台**（`https://bailian.console.aliyun.com/`）创建 API Key（形如 `sk-...`）
2. **Windows 设置环境变量（永久生效）**：打开命令提示符（或 PowerShell）执行：
   ```bat
   setx OPENAI_API_KEY "sk-你的key"
   ```
3. 重新打开终端（或重启电脑）后生效；已启动的服务需重启后才读取到新变量
4. 验证：`echo %OPENAI_API_KEY%` 能看到 key 即配置成功

> 该变量名虽叫 `OPENAI_API_KEY`，实际指向的是**阿里云百炼的 key**（走 OpenAI 兼容协议），不是 OpenAI 官方 key。

## 一键启动

### Windows 用户（最简单）

双击 **`_start.bat`** 即可。脚本会自动：
1. 检测 Python（`python` / `py` / Anaconda）
2. 若缺少依赖，自动执行 `pip install -r requirements.txt`
3. 启动服务器并保持窗口打开，横幅显示老人端/家属端地址与**手机访问用的局域网 IP**
4. 端口被占用时，输入 `R` 可停止旧进程并重新启动，或直接回车打开已运行页面

> 若提示找不到 Python，请先安装 Python 3.10+（https://www.python.org/downloads/ ，安装时勾选 **Add Python to PATH**）。

### 环境要求与常见问题（新机器/客户）

**环境要求**
- Python **3.10 及以上**（推荐 3.10–3.13，从 python.org 安装，务必勾选 **Add Python to PATH**）
- 首次运行会自动安装依赖（`pip install -r requirements.txt`），需联网

**常见问题**

| 现象 | 原因与解决 |
|------|-----------|
| 提示 `Python was not found` / `python 无法运行` | Windows"应用执行别名"把 `python` 指到了 Microsoft Store 占位符。设置 → 应用 → 高级应用设置 → 应用执行别名，关闭 `python.exe` / `python3.exe`；或在命令行用 `py -3` 代替 `python` |
| 自动安装依赖失败 | 手动执行 `python -m pip install -r requirements.txt`（网络慢可加国内镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`） |
| 双击 `_start.bat` 一闪而过/直接关闭 | 在命令行（cmd）里运行 `_start.bat` 查看错误输出，按上方常见问题处理 |
| 后端启动了但浏览器打不开页面 | 确认后端窗口出现 `Uvicorn running on http://0.0.0.0:8000`；端口 8000 被占用时先关闭占用程序 |
| 文字推荐结果"不相干" / 语音识别接口返回 422 | 说明后端**没读到 `OPENAI_API_KEY`**（大模型未启用，退回本地解析）。访问 `http://localhost:8000/api/status` 看 `llm.configured` 是否为 `true`；需在设置环境变量后**重启后端**才能生效 |
| 手动启动报错找不到 `data/meals.json` | 必须在**项目根目录**下启动，不要在子目录里执行 `uvicorn` |

## 演示重置与降级

- **重置**：`POST /api/demo/reset` 一键清空订单、规则、留言并刷新首页；可直接 `curl -X POST http://localhost:8000/api/demo/reset`。
- **AI 降级**：未配置 `OPENAI_API_KEY`、断网或超时时，推荐自动切回本地规则，接口返回 `ai_mode: "local"`。
- **预算硬过滤**：推荐链路对预算做**硬过滤**——家属规则 `max_price` 与用户输入中解析出的价格上限（如"30元以内"）都会直接剔除超预算餐品，绝不推荐超出预算的餐食。
- **无合格餐品 / 未命中需求**：当所有餐品都被家庭规则（预算/禁止食材/饮食偏好）或用户预算排除时，接口返回 `422 NO_ELIGIBLE_MEAL`，前端提示老人放宽条件后重试；当老人提到的具体餐食在菜单中不存在、但仍有符合规则的餐食时，推荐页顶部由大模型生成"未找到+替代推荐"提示语并返回替代餐食，不再直接报错。
- **离线行为（不产生假定单）**：后端断开时，老人端**下单、推进状态、确认收餐、取消订单**均**明确报错、不假装成功**，且**不创建任何模拟/假定单**（`ORD-OFFLINE`/`ORD-DEMO` 已移除）。完整流程需后端在线。设计原因：避免用户误以为操作完成、后端重连后数据不一致。

## 淘宝生态接入指南

### 适配架构

本项目从架构上已支持淘宝生态接入，核心原则是 **`core/` 业务逻辑层与平台无关**，只需新增适配层：

```
当前（Demo）         后期（淘宝小程序）
┌──────────────┐    ┌──────────────────┐
│  Web API      │    │  淘宝小程序前端   │
│  (adapters/   │    │  (支付宝小程序)   │
│   web_api.py) │    └──────┬───────────┘
└──────┬───────┘           │
       │ HTTP              │ 淘宝开放平台 API
       ▼                   ▼
┌──────────────┐    ┌──────────────────┐
│  core/       │    │  core/           │ ← 无需修改
│  业务逻辑     │    │  业务逻辑         │
└──────┬───────┘    └──────┬───────────┘
       │                   │
       ▼                   ▼
┌──────────────┐    ┌──────────────────┐
│ mock_repo    │    │ taobao_repo      │ ← 新增
│ (JSON 模拟)  │    │ (淘宝开放平台API) │
└──────────────┘    └──────────────────┘
```

### 接入步骤

1. **新增适配器**：在 `app/adapters/` 下创建 `taobao_miniapp.py`，实现淘宝小程序后端适配
2. **新增数据仓库**：在 `app/repositories/` 下创建 `taobao_repo.py`，对接淘宝开放平台 API（商品查询、订单管理等）
3. **前端重写**：使用淘宝小程序（支付宝小程序）框架重写前端页面，调用与 `adapters/` 对应的接口
4. **复用业务逻辑**：`app/core/` 下的所有服务无需修改，直接复用

### Demo 说明

当前 Demo 所有订单、支付、配送、联系入口均为**模拟/演示**性质，不做真实平台接入。后端断开时**不创建任何模拟订单**，下单、推进状态、确认收餐、取消订单均明确报错，需后端在线才能完成订单全流程。
